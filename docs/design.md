## 1. 产品定位

### 1.1 一句话描述

一个本地运行的 Web 应用，自动将你的零散资料编译成结构化的 Obsidian 知识库，并用 LLM 驱动问答和持续增强。

### 1.2 目标用户

- 研究者（学术研究、行业研究）
- 终身学习者
- 知识工作者

### 1.3 核心价值

| 价值点 | 描述 |
|--------|------|
| 📥 多源导入 | URL、PDF、视频、代码 → 一键入库 |
| 🔨 自动编译 | LLM 生成带双向链接的 wiki 文章 |
| 💬 智能问答 | 对知识库提问，答案可沉淀回库 |
| 📁 本地优先 | 所有数据在你的 Obsidian vault 里，完全掌控 |

### 1.4 产品愿景

先打造一套可用、有价值的个人工具，后续根据发展情况决定开源或商业化路径。

## 3. 核心功能设计 (MVP)

### 3.1 智能导入 (Ingestion)

**支持的来源**：

| 来源 | 处理方式 |
|------|----------|
| 网页 URL | 抓取 → 提取正文 → 下载图片本地化 → 存为 markdown |
| PDF 文件 | 提取文本 → OCR（如需）→ 存为 markdown |
| YouTube/B站视频 | 提取字幕/转录 → 存为 markdown |
| GitHub 仓库 | 克隆 → 分析 README + 关键文件 → 生成摘要 |
| 本地文件 | 直接拖拽上传 |

**导入流程**：

```
用户输入 URL/文件
     ↓
┌─────────────────────────────────┐
│  1. 识别来源类型                 │
│  2. 调用对应 Parser 解析         │
│  3. 提取：标题、正文、图片、元数据 │
│  4. 存入 raw/{type}/{id}.md     │
│  5. 更新索引                     │
└─────────────────────────────────┘
     ↓
前端显示导入成功 + 预览
```

**UI 设计**：
- 首页一个大的输入框（类似搜索引擎）
- 支持拖拽文件到页面任意位置
- 导入队列显示进度和状态

### 3.2 知识编译 (Compilation)

**触发方式**：
- 手动触发：点击"编译"按钮
- 自动触发：当 raw/ 有新内容时提示编译

**编译流程**：

```
读取 raw/ 中未处理的文档
     ↓
┌─────────────────────────────────┐
│  LLM 处理每篇文档：               │
│  • 生成结构化摘要                 │
│  • 提取关键概念                   │
│  • 识别相关实体                   │
│  • 生成 wiki/ 下的文章            │
└─────────────────────────────────┘
     ↓
┌─────────────────────────────────┐
│  全局处理：                       │
│  • 分析所有文章，发现关联         │
│  • 生成 [[双向链接]]              │
│  • 创建/更新概念词条              │
│  • 更新 index.md 总索引          │
└─────────────────────────────────┘
     ↓
wiki/ 更新完成，Obsidian 可见
```

**生成的 Wiki 结构**：

```
wiki/
├── index.md                    # 总索引 + 最近更新
├── concepts/
│   ├── machine-learning.md     # 概念词条
│   └── transformer.md
├── sources/
│   ├── 2024-01-15-attention-paper.md   # 文献摘要
│   └── 2024-01-20-某博客文章.md
└── connections/
    └── ml-architecture-evolution.md    # LLM 发现的连接文章
```

### 3.3 问答界面 (Q&A)

**问答 UI**：

```
┌─────────────────────────────────────────────────────┐
│  💬 Ask your knowledge base                         │
│  ┌─────────────────────────────────────────────┐    │
│  │ Transformer 和 LSTM 的核心区别是什么？       │    │
│  └─────────────────────────────────────────────┘    │
│                                                     │
│  🤖 Answer                                          │
│  ┌─────────────────────────────────────────────┐    │
│  │ 基于 [[transformer]] 和 [[lstm]] 的分析...   │    │
│  │                                              │    │
│  │ 主要区别：                                   │    │
│  │ 1. 并行性：Transformer 支持完全并行...       │    │
│  │ 2. 长距离依赖：使用注意力机制...             │    │
│  │                                              │    │
│  │ 相关文章：[[attention-paper]] [[lstm-note]]  │    │
│  └─────────────────────────────────────────────┘    │
│                                                     │
│  [📄 存入知识库] [📋 复制] [🔄 重新生成]            │
└─────────────────────────────────────────────────────┘
```

**问答后端流程**：

```
用户问题
    ↓
┌─────────────────────────────────┐
│ 1. 检索相关文档                  │
│    • 关键词搜索 (SQLite FTS)     │
│    • 语义相似度 (embedding)      │
│    • 取 Top-K 相关文档           │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│ 2. 构建 LLM Prompt               │
│    • 注入相关文档内容            │
│    • 指令：回答并引用来源        │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│ 3. 调用 LLM 生成回答             │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│ 4. (可选) 存档到 outputs/        │
│    • 用户点击"存入知识库"        │
│    • 回答变成可搜索的 wiki 文章  │
└─────────────────────────────────┘
```

## 4. 数据模型

### 4.1 文件结构（Obsidian 兼容）

```
your-vault/
│
├── .wiki/                          # 产品私有目录（隐藏）
│   ├── metadata.db                 # SQLite 索引数据库
│   ├── config.json                 # 用户配置
│   └── embeddings/                 # 向量索引（可选）
│
├── raw/                            # 原始资料（只读视图）
│   ├── web/
│   │   └── {id}.md                 # 前置 YAML + 正文
│   ├── papers/
│   │   └── {id}.md
│   ├── videos/
│   │   └── {id}.md
│   └── code/
│       └── {id}.md
│
├── wiki/                           # LLM 编译的知识库
│   ├── index.md                    # 总索引
│   ├── concepts/                   # 概念词条
│   ├── sources/                    # 来源摘要
│   └── connections/                # 发现的关联
│
└── outputs/                        # 生成的输出
    ├── answers/                    # 问答存档
    └── slides/                     # 幻灯片 (Marp)
```

### 4.2 Markdown 文件格式

**Raw 文档格式**（原始资料）：

```markdown
---
id: abc123
type: web
source: https://example.com/article
title: Attention Is All You Need
created: 2024-01-15
tags: [transformer, attention, nlp]
status: pending  # pending / processed
---

# Attention Is All You Need

[原始正文内容...]

![[images/abc123-fig1.png]]
```

**Wiki 文档格式**（编译后）：

```markdown
---
id: wiki-001
source_ids: [abc123, def456]  # 关联的 raw 文档
created: 2024-01-16
updated: 2024-01-20
---

# Transformer

## 摘要
Transformer 是一种基于自注意力机制的神经网络架构...

## 核心概念
- [[self-attention]]
- [[positional-encoding]]
- [[multi-head-attention]]

## 相关来源
- [[abc123]] - Attention Is All You Need (原论文)
- [[def456]] - Transformer 详解 (博客)

## 相关概念
- [[lstm]] | [[rnn]] | [[bert]]
```

### 4.3 SQLite 索引结构

```sql
-- 文档索引
CREATE TABLE documents (
    id TEXT PRIMARY KEY,
    type TEXT,           -- web/paper/video/code
    path TEXT,           -- 文件路径
    title TEXT,
    status TEXT,         -- pending/processed
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    metadata JSON        -- 灵活扩展字段
);

-- 全文搜索索引
CREATE VIRTUAL TABLE documents_fts USING fts5(
    id, title, content,
    content='documents',
    content_rowid='rowid'
);

-- 概念/实体表
CREATE TABLE concepts (
    id TEXT PRIMARY KEY,
    name TEXT,
    wiki_path TEXT,
    mention_count INTEGER,
    created_at TIMESTAMP
);

-- 文档-概念关联
CREATE TABLE doc_concepts (
    doc_id TEXT,
    concept_id TEXT,
    relevance_score REAL,
    PRIMARY KEY (doc_id, concept_id)
);

-- 链接关系
CREATE TABLE links (
    from_path TEXT,
    to_path TEXT,
    link_type TEXT,      -- explicit/inferred
    PRIMARY KEY (from_path, to_path)
);
```

### 5.2 关键依赖选择理由

| 依赖 | 选择理由 |
|------|----------|
| **LiteLLM** | 统一 API，支持 100+ 模型，用户只需配置 API Key |
| **SQLite** | 本地优先，无需额外服务，Obsidian 用户熟悉 |
| **FastAPI** | Python 生态，异步支持，自动 API 文档 |
| **React** | 组件化，生态丰富，产品化体验 |
| **SQLite-vec** | 轻量向量搜索，无需独立服务 |

## 6. 配置设计

### 6.1 用户配置文件

用户在首次启动时配置 `.wiki/config.json`：

```json
{
  "vault_path": "/path/to/your-vault",
  "llm": {
    "default": "gemini-3-pro",
    "providers": {
      "gemini": {
        "api_key": "env:GEMINI_API_KEY",
        "models": ["gemini-3-pro", "gemini-2.5-flash"]
      },
      "openai": {
        "api_key": "env:OPENAI_API_KEY",
        "models": ["gpt-4o", "gpt-4o-mini"]
      },
      "anthropic": {
        "api_key": "env:ANTHROPIC_API_KEY",
        "models": ["claude-sonnet-4-6", "claude-opus-4-6"]
      },
      "ollama": {
        "base_url": "http://localhost:11434",
        "models": ["llama3.2", "qwen2.5"]
      }
    }
  },
  "embedding": {
    "provider": "openai",
    "model": "text-embedding-3-small"
  },
  "compilation": {
    "auto_compile": true,
    "batch_size": 5
  }
}
```

### 6.2 环境变量

用户需要设置的环境变量：

```bash
# .env 文件或系统环境变量
GEMINI_API_KEY=your-gemini-api-key
OPENAI_API_KEY=your-openai-api-key
ANTHROPIC_API_KEY=your-anthropic-api-key
```

### 7.3 典型使用场景

**场景 1：导入并编译新资料**

1. 用户粘贴论文 URL → 系统自动识别并下载
2. 系统显示导入进度 → 解析完成
3. 提示"3 篇新文档待编译" → 用户点击"编译"
4. 后台 LLM 处理 → 生成 wiki 文章 + 概念词条
5. 用户在 Obsidian 中查看新内容

**场景 2：对知识库提问**

1. 用户切换到"问答"标签
2. 输入："Transformer 相比 RNN 的优势是什么？"
3. 系统检索相关文档 → LLM 生成回答
4. 回答中包含 [[wiki-link]] 引用
5. 用户点击"存入知识库" → 回答变成新文章

**场景 3：定期维护**

1. 系统检测到知识库增长到一定规模
2. 提示执行"健康检查"
3. LLM 分析：发现重复概念、缺失链接、可合并文章
4. 用户确认后自动修复
